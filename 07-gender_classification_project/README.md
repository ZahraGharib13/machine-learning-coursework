# Social Profile Gender Classification

An educational machine-learning project for binary classification of the `gender` label from social-profile text and metadata.

The main value of this project is the use of a **heterogeneous scikit-learn pipeline**: numerical, categorical, boolean, and text features are processed in parallel with `ColumnTransformer` and then combined for classification with `LinearSVC`.

> **Responsible-use note:** Gender is a sensitive personal attribute. This repository is an educational ML exercise only. The model may learn cultural, linguistic, and sampling biases and should not be used to make decisions about people.

## Dataset

The training dataset contains **8,000 rows and 10 columns**.

The target column is:

- `gender`

The input features are:

| Feature | Type | Role |
|---|---|---|
| `age` | categorical | age-group information |
| `fullname` | text | profile name |
| `username` | text | account username |
| `biography` | text | free-text profile biography |
| `follower_count` | numerical | number of followers |
| `following_count` | numerical | number of followed accounts |
| `is_business` | boolean | business-account flag |
| `is_verified` | boolean | verification flag |
| `is_private` | boolean | privacy flag |

The original training data had only a very small amount of missing data in `is_business`; missing-value handling is therefore kept inside the preprocessing pipeline so the same logic is applied consistently to training, validation, and test data.

## Feature Engineering and Preprocessing

Different feature types are handled separately.

### Numerical features

```text
follower_count
following_count
```

Pipeline:

```text
median imputation
    ↓
log1p transformation
    ↓
StandardScaler
```

The log transform reduces the effect of strong right-skew in follower/following counts.

### Categorical feature

```text
age
```

Pipeline:

```text
most-frequent imputation
    ↓
OneHotEncoder(handle_unknown="ignore")
```

### Boolean features

```text
is_business
is_verified
is_private
```

Missing values are filled with the most frequent value.

### Full name

`fullname` is represented with character-level TF-IDF:

```text
analyzer = "char"
ngram_range = (2, 5)
min_df = 2
```

Character n-grams are useful for names because they capture spelling variants, transliterations, prefixes, suffixes, and partial patterns.

### Username

`username` also uses character-level TF-IDF:

```text
analyzer = "char"
ngram_range = (2, 5)
min_df = 2
```

This representation works well with shortened words, underscores, digits, and spelling variations.

### Biography

`biography` uses word-level TF-IDF:

```text
ngram_range = (1, 2)
min_df = 2
```

Unigrams and bigrams capture meaningful words and short phrases from profile biographies.

## Complete Pipeline

```text
follower_count ─┐
following_count ─┴─> impute → log1p → scale

age ────────────────> impute → one-hot encode

boolean flags ──────> impute

fullname ───────────> character TF-IDF (2–5 grams)
username ───────────> character TF-IDF (2–5 grams)
biography ──────────> word TF-IDF (1–2 grams)

all features ───────> ColumnTransformer
                         ↓
                     LinearSVC
```

The classifier is:

```python
LinearSVC(
    C=1.0,
    random_state=42
)
```

---

## Why LinearSVC?

TF-IDF creates a high-dimensional sparse feature matrix. Linear SVM models are a strong fit for this type of representation because they are efficient and work well with sparse text features.

## Limitations

This task uses profile names, usernames, biographies, and metadata to predict a sensitive attribute.

The model can encode biases related to:

- language
- culture
- naming conventions
- dataset composition
- self-presentation patterns
- binary target labeling

Therefore, the validation result should be interpreted only as performance on this dataset, not as evidence that the model generalizes fairly or reliably to real populations.

## Possible Next Step
